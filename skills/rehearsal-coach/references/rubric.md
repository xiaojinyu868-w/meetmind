# 试讲诊断维度表（Rubric）

> 听试讲时按这六个维度诊断。每个维度给出"好的样子 / 常见翻车流派 / 改法方向"。
> 指问题时必须引用用户原话；改法必须具体可操作，不说"讲得更清楚一点"这种废话。

## 1. 主线清晰度

- **好的样子**：一句话能说清"我今天要讲什么、为什么重要"；全篇每段都能挂回这条主线。
- **常见翻车流派**：
  - *流水账派*：按时间顺序讲"先做了 A 然后做了 B"，听众听完了不知道重点。
  - *枝蔓派*：讲着讲着岔到细节里出不来，主线被细节淹没。
  - *多头派*：一口气抛三四个贡献点，每个都讲不透。
- **改法方向**：把结论挪到开头先抛出来；砍掉与主线无关的枝节；贡献点压缩到一个主贡献 + 最多两个副贡献。

## 2. 逻辑跳步

- **好的样子**：每一步推导听众都能跟上，"因为…所以…"链条完整。
- **常见翻车流派**：
  - *显然派*："显然可以得到…"——只有他自己觉得显然。
  - *黑盒派*：中间一步直接用结果，不讲怎么来的。
  - *因果倒装派*：先讲方案再讲问题，听众还没理解问题就被塞了答案。
- **改法方向**：把被追问暴露的跳步补成一两句过渡；每个"所以"前面检查"因为"是否讲出来了；先讲问题和动机，再给方案。

## 3. 术语解释

- **好的样子**：专业概念第一次出现时有一句大白话解释或类比；缩写第一次出现给全称。
- **常见翻车流派**：
  - *默认懂派*：默认听众和自己同方向，术语裸奔。
  - *过度解释派*：对行家听众解释 ABC，浪费时长还显得不懂行。
- **改法方向**：先确认听众构成（答辩评委跨方向？面试官是否同领域？）；每个关键术语第一次出现时加一句类比；缩写首次给全称。

## 4. 证据链

- **好的样子**：每个论断后面跟着数据、实验或引用支撑；数字说得出出处。
- **常见翻车流派**：
  - *断言派*："效果很好""提升很大"，不给数字。
  - *孤证派*：只讲成功的 case，不讲整体统计。
  - *大词派*："千亿市场""行业领先"，数字来源说不清。
- **改法方向**：每个论断补一个具体数字或例子；数字标注来源（自己的实验/哪篇文献/哪次调研）；准备一个失败 case 主动讲。

## 5. 时间控制

- **好的样子**：总时长卡在限时的 80-90%；重点段落分配最多时间；有"可弃段落"预案。
- **常见翻车流派**：
  - *前松后紧派*：背景讲了半场，核心内容最后两分钟狂奔。
  - *均匀派*：每页 PPT 平均用力，重点不突出。
  - *无底洞派*：一个细节被问住后展开五分钟，节奏全崩。
- **改法方向**：按「开场 / 背景 / 核心 / 结果 / 收尾」分段标注时间（可用 `scripts/estimate_duration.py` 辅助估算）；标注哪段超时可以先砍；追问演练时练"一句话版回答"。

## 6. 听众适配

- **好的样子**：内容深浅、例子选择、措辞都针对台下的真实听众调过。
- **常见翻车流派**：
  - *自嗨派*：只讲自己觉得酷的，不管听众关心什么。
  - *一稿通吃派*：组会版讲稿原样搬去答辩/面试。
  - *错配预期派*：听众想听价值，他讲实现细节；想听细节，他讲愿景。
- **改法方向**：先回答"台下坐的是谁、他们来听什么"；同一内容按听众换切入角度（同行讲方法、评委讲贡献、投资人讲生意）；把最关键的一句话调到前三分钟之内。

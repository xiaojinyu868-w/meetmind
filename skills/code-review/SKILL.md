# Code Review

> 本 skill 定义代码审查的标准。agent 每次完成变更后自审，或审查其他 agent 的变更。

## 触发条件

- 完成一组变更后
- 被要求审查代码时
- 提交前最终检查

## 审查清单

### 第一轮：正确性

- [ ] `make check` 零错误
- [ ] 变更完成了声称的目标（不多不少）
- [ ] 没有引入新的 `console.log`（用 logger）
- [ ] 没有硬编码的魔术值（用常量或配置）
- [ ] 错误处理完整（try/catch 有意义的 error message）

### 第二轮：架构合规

- [ ] 文件大小未超 500 行（新文件）
- [ ] 依赖方向正确（services 不 import components）
- [ ] 新类型定义在 `src/types/` 中（如果是共享的）
- [ ] API 路由是薄层（逻辑在 services/）
- [ ] 设计系统合规（零渐变、零阴影、系统 token）

### 第三轮：可维护性

- [ ] 函数名和变量名自解释
- [ ] 复杂逻辑有注释（说 why 不说 what）
- [ ] 没有重复代码（≥3 次出现的模式应提取）
- [ ] 导出接口稳定（改接口要更新所有消费方与对应文档）

## 问题严重等级

| 等级 | 含义 | 示例 | 处理 |
|------|------|------|------|
| **P0 阻塞** | 必须修复才能提交 | `make check` 报错、运行时崩溃、安全漏洞 | 立即修复 |
| **P1 重要** | 应该在本次修复 | 架构违规、缺少类型、超大文件 | 当次修复 |
| **P2 建议** | 可以后续修复 | 命名优化、注释缺失、可提取的重复 | 记录到 TODO |

## 审查输出格式

```
## 审查结果

### P0 阻塞
- [无]

### P1 重要  
- `src/xxx.ts:42` — 缺少错误处理，fetch 失败会导致未捕获异常

### P2 建议
- `src/xxx.ts:15` — `data` 变量名不够自解释，建议改为 `echoSegments`

### 总结
变更 [通过/需要修复]，[N] 个问题待处理。
```

# 讲演幻灯片设计方法论

这份 PPT 为"讲"而做，不为"展示"而做：幻灯片是听众的视觉锚点，细节在讲者嘴里，口播稿在讲者备注里。出讲演骨架和写 slides.txt 时按这份方法论来。

## AST：每页是一次观众状态转移（Audience State Transition）

命名与思想来自 humanize-ppt（MIT，https://github.com/LearnPrompt/humanize-ppt）：一副 deck 不是大纲的堆叠，而是一条**观众状态转移弧**——每页负责把观众从一个认知状态带到下一个。

- 每页四件套：**论断标题**（这页的结论）+ **意图**（`~ 观众离开这页时应该相信/感受到什么`）+ **视觉锚点**（屏幕上只放关键词和数字）+ **口播要点**（嘴上说的话，进 `>> ` 备注）。
- 意图行不渲染进幻灯片，它是给做 PPT 的人和体检脚本看的：写不出意图的页，往往是不必要的页。
- 与用户确认的不是"大纲"，而是状态转移弧：把每页意图连起来读一遍，观众应当被一步一步地带到结论；断掉的地方就是叙事断掉的地方。
- 生成后用 `check_deck.py` 体检：意图缺失、栏目名标题、要点密度、口播稿缺失、节奏配比、章节结构都会被逐条点名。
- 时长用 `%duration`（分钟）声明，体检据此判断页数是否讲得完——经验值约 1 页/分钟。

## Assertion-Evidence：标题是一句论断（Michael Alley, Penn State）

- 每页标题是一句**完整的论断**（takeaway），不是栏目名：「多跳问答准确率从 58% 提升到 78.5%」，不是「实验结果」。
- 为什么：听众走神回来、或只读标题翻一遍，也能跟上整场论证主线——把每页标题连起来读，就是你的论文摘要。
- 检验方法：把所有标题单独列出来读一遍，读不通的地方就是叙事断掉的地方。
- 栏目名（研究背景 / 实验结果）留给「章节：」过渡页用，内容页标题一律论断句。
- 本技能的内容页标题 >20 字自动降为 20pt 两行排版，论断句写全不用省字。

## 10/20/30 法则（Guy Kawasaki）

- **≤10 页**正文：页数强迫你取舍，取舍强迫你想清楚主线。
- **≤20 分钟**：留时间给提问，提问环节才是组会和答辩的真正战场。
- **字号 ≥30pt**：英文场景的标准；中文课堂可放宽到正文 ≥18pt，但标题不低于 20pt。字号下限是防止文字墙的硬约束。

## 每页一个信息点（6×6 的精神）

- 一页只讲一件事；标题就是这事的结论，正文是它的证据锚点。
- 要点 ≤6 行、每条 ≤6 个词组的精神：幻灯片上是**关键词和数字**，不是句子。完整句子留给嘴。
- 字要少，话要多：如果幻灯片上的字读完等于讲完了，那讲者是多余的。

## 讲者备注 = 口播稿

- slide 给听众看，notes 给讲者看——`>> ` 行写的就是这页嘴上要说的话。
- 备注里写什么：这页的开场过渡句、数字背后的解释、预料中的提问和回答方向、时间提示。
- 备注不是把要点抄一遍——要点在屏幕上，备注是屏幕上没有的那部分。
- 放映时开演示者视图（Presenter View）才能看到备注；打印备注页可以当提词卡。

## 注意力曲线与强调页

- 听众注意力在开场后约 10 分钟衰减一次，需要"重置"。
- **开场 30 秒钩子**：第一页内容页直接抛痛点或最反直觉的结果，别从"研究背景"慢慢爬。
- **强调页（`# 强调：`）的使用时机**：全场 1-2 张，放在核心结论处——整页只有一句话，讲者停顿、让这句话沉下去。用多了等于没用。
- 章节过渡页也有重置注意力的作用，长汇报（>10 页）用它把汇报切成 10 分钟以内的小段。

## 组会 vs 答辩 vs 路演

| 维度 | 组会汇报 | 毕业/项目答辩 | 竞赛路演 |
|------|---------|--------------|---------|
| 主线 | 进展→卡点→下一步 | 问题→方法→结果→结论 | 痛点→方案→证据→愿景 |
| 背景 | 一页带过，听众是同行 | 要讲透，评委未必同方向 | 只讲痛点，不讲技术史 |
| 弱点 | 主动暴露，求助是目的 | 放进附录，被问再翻 | 转化为"下一步计划" |
| 结尾页 | 下一步 + 需要的支持 | 结论复述 + 贡献清单 | 一句话愿景 + 联系方式 |
| 附录页 | 不需要 | 强烈建议：补充实验/推导放「谢谢聆听」后 | 财务/技术细节备查 |

## 视觉审美：高级感从哪来

吸收 anthropics/skills 官方 pptx skill 与演示设计经典（iSlide、slide:ology、Storytelling with Data）的交叉共识。生成器已内建以下规则，写骨架时理解它们，就不会和模板打架。

**明暗三明治**：封面页与结尾页整页深紫底，内容页浅色——首尾深色包住中间浅色，是 premium 演示的经典结构。不要摇摆（一会儿深一会儿浅的内容页最显廉价）。

**配色纪律**：全 deck ≤5 色，且有主导色不均分——清华紫 `#660874` 主导（封面/章节/强调/标题栏），浅紫灰 `#F3EEF7` 辅助，正文 `#333333`，辅助灰 `#808080`，纯白底。强调色每屏只服务一个焦点。正文文字对背景对比度 ≥4.5:1（白字 on 紫底约 9:1，达标）。

**字号层级要悬殊**：封面 40pt / 章节 40pt / 强调页 54pt / 内容页标题 28pt（长标题 22pt 两行）/ 正文 18pt / 二级 16pt / 页脚 10.5pt。标题与正文的字号差必须拉得够开——层级感主要靠字号差而不是颜色花哨。全 deck 只用一种字体家族（微软雅黑），用字重而非换字体分层。

**留白与对齐**：页边距统一 ≥0.6"，内容区与标题栏间距统一 0.44"——间距全 deck 选一档就不显乱。正文一律左对齐，只有封面/强调页居中。拥挤 = 低端感：写不下就拆页，不要缩字号塞。

**NEVER 清单（明星 skill 的"AI 味"雷区，本模板已规避，用户二次编辑时也别加回来）**：
- 标题下加下划横线——AI 生成幻灯片的标志性特征；分区靠留白和底色，不靠线
- 装饰性色条/侧边竖条/卡片单边描边——区分内容用浅底色或间距，不用装饰条
- 默认奶油/米色背景、默认蓝——没理由就纯白
- 只有封面打扮、其余裸奔——要么全 deck 统一风格，要么全简

**3 秒扫视测试（Duarte glance test）**：每页 3 秒内能被理解；一页超过 75 个词就退化成了文档而不是幻灯片。这与"每页一个信息点"互为表里。

**图表审美（用户在 PowerPoint/WPS 里自行插图时的嘱咐）**：删图表边框 → 淡化/删网格线 → 数据直接标注取代图例 → 把关键数据点涂成紫色、其余降为中性灰（preattentive attribute，最强的一招）。禁 3D 图表、渐变、阴影。图表页标题写洞察（"准确率提升 20.5%"）不写描述（"实验结果对比图"）。

## HTML 视觉系统（v5 主交付）

v5 起主交付是单文件 HTML 讲演 deck（`make_html.py`）。方法论上参考了 guizang-ppt-skill（AGPL-3.0，**只吸收设计参数，代码全部原创**）与 anthropics/skills 官方 pptx skill；风格对齐瑞士国际主义（Swiss / International Typographic Style）。以下规则已内建于生成器，写骨架时理解它们即可。

**Token（:root，主题固定清华紫，不提供自选色）**

- `--paper:#FBFAFC` 微紫暖白（禁纯白）、`--ink:#16101C` 近黑（禁纯黑）、`--accent:#660874` 清华紫、`--accent-on:#FFF`
- 灰阶：`--grey-1:#F3EEF7`、`--grey-2:#DDD3E4`、`--grey-3:#7A7285`、发丝线 `--border-subtle:#E8E2EE`
- 字体全部走系统字体栈（不用任何 webfont CDN——教室离线必须可放映）：sans 栈 `Inter → -apple-system → Segoe UI → PingFang SC → Hiragino Sans GB → Noto Sans SC → Microsoft YaHei`；mono 栈 `ui-monospace → SF Mono → Cascadia Code → Consolas`（仅 chrome/页码/标签，uppercase + letter-spacing .15em）。间距按 8px 基线。

**字号/字重双阶梯（越大越细）**

大字一律 `min(Xvw, Yvh)` 双约束防 vh 截断（Y≥1.6X）：封面主标题 `min(7vw,12vh)` weight 200、强调页单句 `min(6vw,10.5vh)` w200、章节页 `min(4.6vw,8vh)` w200、KPI 大数字 `min(6vw,10vh)` w200 + `tabular-nums`；内容页论断标题 `min(2.5vw,4.4vh)` w400（中文长句不做超细）；正文 `max(18px,1.15vw)` lh1.65，二级 `max(16px,1vw)` 灰，chrome/页脚 mono `max(13px,.8vw)`。**投屏下限**：正文 ≥18px、注释 ≥16px、meta ≥13px；16px 小字禁 weight<400。强调字用 italic（标题里 `*强调字*`），不用 accent 色压紫底。

**瑞士纪律**

直角、无阴影、无渐变、无圆角；装饰只允许 1px 发丝线与小色块（一级要点的 8×8 紫方块、数据页列顶 2px 紫线、内容页标题下 1px 发丝线）。页面框架统一：顶部 chrome（左 mono 栏目标签、右 `NN / TOTAL`）→ 主内容（padding 统一 `5.5vh 5vw 7vh`）→ 底部发丝线 + 左「清华大学」+ 右页码。内容页要点区 max-width 约 62% 左对齐，右侧留白（不对称网格）。

**七种页型（data-layout 白名单）**

COVER（满屏紫底，mono kicker + 垂直居中大标题 + 底部发丝线 author/date）/ SECTION（紫底，mono 章节序号 opacity .25 背景化 + 章节标题）/ STATEMENT（紫底整页一句论断）/ CONTENT（白底，mono 紫 kicker「论点 NN」+ 论断标题 + 两级要点）/ DATA（白底，2-4 stat 列，焦点列紫底反白——默认第一列或注释含"焦点"的列）/ COMPARE（白底左右两半，中缝 1px 竖线，左半 opacity .62 表旧/现状）/ CLOSING（左半紫底「谢谢聆听」+ 右半白底 takeaway，第 3 条紫色与封面色彩闭环；无要点则整页紫）。

**演讲者模式契约**

- 生成时嵌入 `SPEAKER_NOTES=[{id,title,intent,talk,min}]`（`~` 进 intent，`>>` 进 talk，`%duration` 按页数平摊出每页分钟预算）；`>>`/`~` 内容**绝不进观众屏渲染**。
- 按 `P`：当前窗口变深色控制台（`#101216`）——左侧当前页 16:9 实时预览（deck 容器整体 transform scale，不重载页面），右侧本页口播稿 + intent + 下一页标题预告，底部计时器（开始/继续/重置 + 已进行/剩余）+ `第 N 页 / 共 M 页`。
- 观众屏：`window.open` 同文件 `?audience=1&session=<ts>`，BroadcastChannel（`thu-deck:<session>`）+ postMessage 兜底同步翻页；观众屏回 ack，控制台显示「观众屏已同步 / 未连接」（只在发出 goto 未收到 ack 时才判超时）；弹窗被拦截给提示。退出演讲者模式观众屏显示「演示已结束」。观众模式隐藏导航点与快捷键提示。
- 入场动效为自写极简 CSS+JS（`data-anim` stagger 80ms fade + translateY(12px)），尊重 prefers-reduced-motion，`B` 键静态模式（localStorage 记忆）。不引入任何 JS 库。

## 常见翻车清单

- **标题是栏目名**：「实验结果」没有信息量，听众翻页时就丢了主线。
- **整页文字墙**：一页超过 8 行字，听众开始读字就不听你讲了。
- **照着念**：屏幕上写什么嘴上念什么——备注的存在就是治这个病。
- **强调页滥用**：8 页汇报 4 张强调页，等于没有强调。
- **答辩不做附录页**：被问"补充实验做了吗"时翻不出东西，是最可惜的失分。
- **封面信息不全**：标题、汇报人、单位、日期四件套缺一个都显得不正式。

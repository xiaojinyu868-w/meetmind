# 纯向量检索在多跳问题上准确率不足 60%
~ 观众离开这页时应该相信：纯向量检索撑不起多跳问题
- 基线：大模型 + 向量检索（RAG）
- 多跳问题：需串联 2 个以上事实
- 症结：检索碎片化，推理链断裂
>> 开场先抛痛点：大家以为 RAG 万能，但多跳问题一上就不行。
>> 举一个真实例子："A 的导师的博士生是谁"——向量检索只能拿到一跳。

# 章节：我们的方法

# 知识图谱把推理链变成图上的一条路径
~ 观众从"检索就是向量匹配"转到"推理可以是图上可追溯的一条路径"
- 问题 → 实体链接 → 图查询
- 路径即推理过程，可追溯
  - 每一步对应一条三元组
>> 这一页讲方法核心：把"检索"换成"走路径"。
>> 强调可追溯性——答案错了能定位到哪一步错，这是 RAG 做不到的。

# 对比：从"匹配文本"到"走路径"，检索范式换了一代
~ 观众一眼看清新旧范式的差异，承认路径检索是代际升级
- 检索到的是碎文本片段 | 检索出的是完整推理路径
- 推理过程不可追溯 | 每一步对应一条三元组
- 答案错了无从定位 | 错了能定位到具体哪一跳
>> 对比页不要逐行念，让中缝两边的差异自己说话。
>> 只点一句：左边是"像"，右边是"对"——匹配像的文本，和走出对的路径，是两回事。

# 章节：实验结果

# 数据：多跳问答准确率从 58% 提升到 78.5%
~ 观众从怀疑方法转到承认提升真实、实验公平
- 78.5% | 多跳问答准确率 | 较基线 +20.5pt
- 58.0% | 纯向量检索基线 | CCKS2022 KGQA 评测
- 90.2% | 单跳问题准确率 | 多跳才是拉开差距的战场
>> 先抛结果再解释公平性：同样的大模型、同样的语料，唯一变量是检索方式。
>> 预料会被问"为什么基线这么低"——回答方向：多跳问题本身就是 RAG 的已知短板。

# 强调：推理路径是可解释的

>> 强调页不停留，说完就走：这是我们和所有黑箱方案的本质区别。
>> 用一个具体 case 演示路径长什么样，30 秒讲完翻页。

# 错误主要来自实体链接歧义，占 40%
~ 观众看到我们知道短板在哪，并且短板可被修复
- 同名实体：地名 vs 人名
- 计划：引入上下文消歧模块
>> 主动暴露弱点是组会的本分，别等被问。
>> 下一步计划顺带引出，自然过渡到最后一张内容页。

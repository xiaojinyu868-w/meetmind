# MeetMind 独立产品拆分与上线计划

> 目标：把当前聚合在一个 APP 里的能力拆成几个各自成立的产品。每个产品都有独立入口、首用闭环、核心指标和上线节奏；底层仍共用账号、数据、模型与个人上下文，不复制代码或过早拆成多个后端。

## 1. 产品拆分结论

MeetMind 适合拆成 **3 个独立产品**：

| 产品 | 用户的一句话需求 | 独立输入 | 独立结果 | 建议入口 |
|---|---|---|---|---|
| **MeetMind 课堂** | 把这节课完整听下来并整理好 | 麦克风、电脑声音、已有音视频 | 原声、定稿转录、实时课堂脉络、课后笔记总结 | `/classroom` |
| **MeetMind 学习** | 帮我真正学会这份材料 | 一节课堂、PDF、音视频、网页、文字 | 有证据的问答、闪卡、测验、思维导图等学习成果 | `/study` |
| **MeetMind 收集** | 先替我收好，之后还能找回来、问起来 | 文字、链接、图片、文件、微信消息 | 可检索原件、整理后的来源、跨材料问答 | `/inbox` |

不是每个现有页面或功能都应该变成产品：

- **我的上下文**是三个产品共用的智能底座，不单独售卖，也不做成需要用户维护的“画像产品”。
- **Ask MeetMind**是跨产品的交互能力，在当前产品范围内回答，不做一个没有明确材料边界的通用聊天产品。
- **分享与 SharedAgent**是三个产品共用的成果分发能力。它依附于已经完成的成果，不拥有独立的内容生产闭环。
- **登录、同步、模型选择、管理控制台**是平台能力，不进入主导航争夺用户注意力。
- **闪卡、测验、思维导图等**是 MeetMind 学习里的学习动作；先逐个验证质量，不拆成六个空心小产品。

## 2. Landing Page：统一产品大厅

根 Landing Page 负责解释 MeetMind 的共同价值，并呈现三个独立产品入口；它不承载录音、学习或收集的具体工作流，也不做成罗列所有功能的黄页。

```text
MeetMind 的共同价值
把学习现场留下，并继续变成理解

┌────────────────┐  ┌────────────────┐  ┌────────────────┐
│ 我正在上课      │  │ 我现在要学      │  │ 我先存下来      │
│ MeetMind 课堂   │  │ MeetMind 学习   │  │ MeetMind 收集   │
└────────────────┘  └────────────────┘  └────────────────┘
```

以上只是信息层级，不是最终用户文案；实现时仍统一从 `src/lib/ui/copy.ts` 读取。

Landing Page 对两类用户采用不同重心：

- **第一次访问**：先说明一个共同承诺，再用三个场景入口让用户自选；不展示内部技术、模型或完整功能清单。
- **回访用户**：在三个入口之前只突出一个最值得继续的真实现场，例如正在处理的课堂、未完成的学习动作或最近保存的来源。
- **尚未上线的产品**：可以显示克制的“即将开放”状态或内测登记，不能把用户送进半成品页面。
- **进入产品后**：每个产品使用自己的最小导航，并保留一个安静的返回产品大厅入口；不要在产品内部继续展示另外两个产品的完整功能。

Landing Page 不是第四个产品，也不拥有独立业务数据。它只读取三个产品的轻量索引，用于显示入口状态和“继续上次”，不能读取或重写转录、学习成果和收集正文。

## 3. 产品之间的合同

产品可以互相递交结果，但不能直接读取彼此尚未完成的内部状态。

```text
MeetMind 课堂
  └─ 发布 LessonPackage ─────┐
                             ▼
MeetMind 收集 ──发布 SourcePackage──→ MeetMind 学习
```

三个产品发布的完成态成果都可以按需调用共享的分享能力，生成不可变分享快照；分享不是数据主链路中的第四个产品。

数据联通遵循“底层共用、产品显式消费”：

- 三个产品共用一个账号、Workspace、权限体系和个人上下文。
- MeetMind 课堂完成后，课堂会自然出现在 MeetMind 学习的“最近材料”中，但不会自动生成学习应用。
- MeetMind 收集发布的来源可以在 MeetMind 学习中被选择，但不会自动进入当前学习会话。
- MeetMind 学习只引用课堂或收集发布的稳定版本，不直接修改原始课堂和收集内容。
- 学习中产生的作答、困惑和完成记录可以作为个人上下文的新证据，但不能反向改写来源事实。
- 跨产品跳转必须携带稳定 ID 和明确动作，例如 `lessonId`、`sourceId` 或 `artifactId`；禁止依靠页面内共享临时状态。

### LessonPackage（课堂发布物）

- 原声引用与时长
- 定稿转录及时间戳
- 可靠的说话人信息（若有）
- 课堂脉络与课后笔记总结
- 用户标记的困惑点和个人笔记
- 明确的 `processing / ready / failed` 状态

只有 `ready` 内容能作为 MeetMind 学习或分享快照的事实来源。实时转录草稿不能跨产品发布。

### SourcePackage（收集发布物）

- 原始来源与来源类型
- 解析后的正文或媒体引用
- 来源标题、作者、时间等 provenance
- 解析状态与失败原因

收集失败只影响该来源，不能阻塞整个收件箱或污染个人上下文。

### StudyArtifact（学习发布物）

- 成果类型和结构化内容
- 使用的来源范围
- 可回到原文的证据引用
- 用户作答、自评等学习现场事实

共享的分享能力只消费不可变快照，不读取分享者的私人个人上下文。

## 4. 各产品的最小完整版本

### 产品一：MeetMind 课堂

首用闭环：

```text
打开 → 选择声音来源 → 录课 → 看见实时文字与课堂脉络
     → 结束 → 等待定稿 → 得到原声可回放的课堂笔记
```

首版保留：

- 麦克风 / 电脑声音 / 两路都录
- 原声可靠保存
- 实时转写
- 真正增量的课堂脉络
- 完整原声 batch 定稿
- 基于定稿的标题与结构化笔记
- 原声、转录和时间戳回看

首版移出：

- 学习应用矩阵
- 长期个人上下文编辑
- 今日情报和通用收集流
- 分享海报与 SharedAgent
- 与录课无关的复杂 Tutor 能力

这个产品的北极星不是“转写字数”，而是：**一节真实课程结束后，用户愿意把这份结果当成可信课堂记录留下来。**

核心观测：首次录音成功率、原声完整率、漏段率、停止后定稿成功率、定稿等待时间、七日内第二次录课率。

### 产品二：MeetMind 学习

首用闭环：

```text
放入材料或选择一节课 → AI 判断材料是否足够
  → 基于证据解释 / 出题 / 做闪卡 → 用户完成一次学习动作
  → 保留进度，下次继续
```

首版保留：

- 课堂、PDF、音视频、网页、文字的统一材料入口
- 左侧原件证据、中间学习动作、右侧同学的三栏工作台
- 带时间戳或来源引用的问答
- 闪卡、测验、思维导图；其他应用逐个灰度
- 学习黑板和恢复上次现场

首版移出：

- 实时录课 UI
- 收件箱、今日情报
- 分享管理
- 自动扩大到用户全部历史材料

MeetMind 学习必须能够在没有 MeetMind 课堂的情况下独立使用：用户直接上传一份材料，也能完成完整学习闭环。

核心观测：材料成功进入率、首次学习动作完成率、证据回跳率、一次会话内的有效作答数、七日回访率。

### 产品三：MeetMind 收集

首用闭环：

```text
随手发送一个东西 → 原件立即保存 → 后台解析
  → 以后能按来源找回 → 可以围绕已收内容提问
```

首版保留：

- 文字、链接、图片、文件、微信捕获
- 原件优先保存和失败重试
- 来源列表、搜索、引用与归档
- 基于明确选中范围的 Ask MeetMind
- 跨设备恢复

首版移出：

- 课堂录音和实时脉络
- 完整学习应用矩阵
- 主动推送式今日情报；待收集留存成立后再验证
- 分享 Agent

核心观测：首次捕获成功率、解析成功率、七日内累计捕获数、被重新打开或引用的内容比例、跨设备恢复成功率。

### 共享能力：成果分享

首用闭环：

```text
从一个已完成成果创建分享 → 同学在微信打开
  → 看懂成果并继续追问 → 领取到自己的学习空间
```

分享落地页可以有完整的访客体验，但它仍然是课堂、学习或收集成果的外部延伸，不是一个独立产品。只有来源产品持续产生值得分享的结果时，这项能力才有增长价值。

核心观测：创建分享率、微信打开成功率、打开到对话率、领取率、领取后的首个学习动作完成率，以及零私人上下文泄漏。

## 5. 上线顺序

### 第一阶段：只上线 MeetMind 课堂

原因：课堂是当前最明确的高频现场，也是录音、转写、实时整理和课后笔记问题最集中的地方。先把这一条做成一个可信的独立产品，暂时隐藏收集、应用矩阵和分享等其他叙事。

当前提交 `433cf77` 是课堂产品的第一轮链路修复，但仍需：

1. 独立课堂入口和只包含课堂能力的导航壳。
2. 手机真机固定样本对照，确认首次启动、漏段和定稿等待。
3. 从开始录音到笔记 ready 的完整 session 观测。
4. 内部账号灰度开关和快速回滚能力。

### 第二阶段：上线 MeetMind 学习

课堂稳定后，以 LessonPackage 接入；同时保留直接上传材料的入口，证明它不是课堂的附属页面。先验证 Tutor、闪卡和测验，再逐个开放其他学习动作。

### 第三阶段：上线 MeetMind 收集

先证明“发进去不会丢、以后找得到”，再加入跨内容问答；今日情报和长期学习理解属于后续增强，不能抢在基础收集留存之前。

分享不占用独立的产品上线阶段。每个来源产品稳定后，再为该产品的少数完成态成果开放分享；分享页、对话和领取回流仍作为独立漏斗观测，但不能用分享数据反向掩盖来源产品的成果质量。

## 6. 产品形态与代码策略

第一阶段不拆仓库、不复制后端，也不急着做三套品牌。先采用“一个共享内核、三个产品壳”：

- 独立 URL、首页、空态、导航和首次使用流程。
- 根路径作为产品大厅；登录后仍可直接通过稳定 URL 进入任一已开放产品。
- 独立 feature flag、发布批次和产品指标。
- 共用身份、Workspace、IndexedDB / 服务端同步、模型 provider、设计系统和上下文服务。
- 只通过 LessonPackage / SourcePackage / StudyArtifact 等发布合同跨产品流动数据。
- 当前 `/app` 逐步退为产品选择与兼容入口；新改动落到对应产品壳，不继续扩大 God File。

只有某个产品已经找到独立用户群、发布节奏或扩缩容需求时，才考虑独立域名、部署单元或仓库。现在先拆用户体验和数据边界，避免为了“独立”制造三套重复基础设施。

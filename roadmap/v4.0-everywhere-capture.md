> 2026-07-27 确认的架构方向。本文档是全端采集（桌面壳 / 网页多模态 / 移动壳）与
> 学习上下文引擎（Event→Task、规则 Hook 主动服务）的北极星，地位等同
> `v3.0-virality-agent.md` 之于分享线。
> 调研底稿：四个产品的机制拆解（Granola / Rewind / AirJelly / YouNavi）+
> 浏览器能力边界 + 移动端内录保活 + VLM 成本测算，关键结论文末附来源。

## 一句话

**以「课」为天然锚点的学习上下文引擎：桌面壳负责无感采集，服务端把 Event 流
归纳成学习线索，主动服务只做规则驱动的确定性 Hook。**

## 核心判断（来自调研，不是拍脑袋）

1. **锚点而非全量**（AirJelly）：全量录屏 = 60 分信息 + 5 分错误；锚点采集 =
   50 分信息 + 1 分错误。**人对错误的容忍度远低于遗漏**——一条错误的脉络 /
   推送比少记十件事更伤「这个 AI 真的懂我」的第一印象。MeetMind 的锚点天然
   存在：课的开始/结束、热键截图、PPT 翻页。
2. **Event→Task 层级记忆优于平铺时间线**（AirJelly）：先召回 Task 再下钻
   Event，比全散召回好得多；按任务组织比按时间组织更符合非连续学习行为。
3. **主动服务走规则 Hook，不走模型自主 Proactive**（YouNavi）：「不能放大
   主动性的魔幻感，给用户超预期的幻觉」——与 MeetMind「安静」Taste 同频。
   验收指标抄 AirJelly 的 **Proactive 接收率**：学生是否采纳推荐 = 全链路
   健康度。
4. **国内竞品（通义听悟/飞书妙记）都没有桌面本地双轨采集**（Granola 模式：
   系统音频 loopback + 麦克风，无机器人）。这是空档。
5. **关键帧 + 转录文本喂 VLM 比视频直传便宜两个数量级**（40-80 帧/课 ≈
   ¥0.1/课，qwen3-vl-plus），且语义密度更高。

## 三层架构

### L1 采集层（本期已落地）

```
桌面壳（Electron，desktop/）
 ├─ 内嵌主窗口加载 MeetMind 网页版 → 现有录音/ASR/复习链路零改动
 ├─ setDisplayMediaRequestHandler 自动授予主屏 + loopback 系统音频
 │   （Windows WASAPI / macOS SCK，Chromium flags 见 desktop/main.js）
 ├─ 全局热键 Cmd/Ctrl+Shift+M → 截鼠标所在屏 → upload-image →
 │   captures(sourceType='desktop-screenshot') → 通知；失败落盘补传
 └─ Octo 悬浮球保留，入口统一走壳内主窗口（不再 openExternal）
网页端关键帧（src/lib/services/keyframe/）
 └─ 1fps 缩略帧 pHash（死区防纯色同值簇失稳）→ 稳定 2.5s 结算 →
    翻回旧页去重 → 关键帧带录音时间轴锚点（Rewind 统一时间轴模式）
服务端（本期新增）
 ├─ POST /api/workspace/upload-image（截图/关键帧原图持久化）
 ├─ GET  /api/workspace/images/[user]/[file]（动态路由读盘）
 ├─ POST /api/workspace/captures/[captureId]/artifacts
 │   （kind 自由字符串：keyframe / screenshot，幂等 upsert）
 └─ 微信扫码轮询支持 clientNonce（桌面端免 Cookie 登录）
```

移动端（方向已定，未动工）：**Capacitor 壳 + 自写 Kotlin 插件**。
- Android：MediaProjection + AudioPlaybackCapture 系统内录（API 29+，
  讯飞听见同款；被录方可拒绝、通话类音频永远录不到）；microphone FGS
  前台态启动 + 厂商白名单引导（自启动/电池优化）+ 本地分片落盘断点续传
  （Otter local-first 模式）。保活无银弹，FGS+白名单是业界上限。
- iOS：系统内录不可能（无合规 API，Plaud 靠硬件振动传感器绕）；收敛为
  麦克风 + UIBackgroundModes=audio 可靠后台录音。

### L2 学习线索层（Event→Task，下一里程碑）

现状：转录分段、困惑点、追问、应用练习仍以附着在某节课上的**散点 Event** 为主。
已落地的 Task 底座：深度学习线创建时绑定课堂 `sessionId` 与问答 `conversationId`；深度回答只有在 `global-ask:<conversationId>:` 精确匹配时才作为对话证据写回 Task，同课的测验作答、闪卡自评和讲给同桌听结果会以 `app-interaction:` 证据推进活跃线摘要。账号画像与访客 IndexedDB 都保存最多 16 条 Task 历史和有界课堂/对话/活动证据 ID；切换或完成不会删除历史。“我的上下文”提供进行中/暂停/完成的 Task 控制面，可恢复任一历史 Task，并按显式 Event ID 下钻最近学习现场；事件尚未回温时不做 session 级猜测。今日情报按活跃 Task、历史 Task、记忆、近期 Event 的层级召回，并用状态与证据计数约束编排。完整的自动跨课 Task 归纳、向量/关键词混合召回和时间衰减仍是本层后续工作。
目标：归纳成跨课的**学习线索 Task**：

- Task 字段（AI 判断写入）：主题、摘要、掌握状态、Progress、**Next Step**、
  下属 Event 列表。静态知识建模为 Entity（这门课是什么、这个人是谁）。
- 召回 = 向量 + 关键词 + Agentic RAG + **时间衰减**；先 Task 后下钻 Event。
- 这是 `recentLearningActivities` 客观事件流的升级，也是「收集线课堂线
  不是数据孤岛」的真正落点：收集线回流成线索，课堂线事件更新线索。
- 数据底座已备好：Event 流 = WorkspaceTranscriptSegment +
  WorkspaceCaptureArtifact（anchor/highlight/note/summary/keyframe）。

### L3 主动服务层（规则 Hook，L2 之后）

- 形态：规则驱动 + 用户可自然语言自定义（YouNavi Hook 同款）：
  - 「转写定稿后 → 生成摘要 + 困惑点」（已有，推广为 Hook 机制）
  - 「课后 24h → 今日最该回来的 3 个点」（晚间简报式复习卡）
  - 「某线索连续 3 次课没推进 → 轻提醒」
- 触发规则抄 AirJelly 朴素版：新 Next Step 进推送池 + 阈值 + 频控，
  不做专注度判断。
- 反馈形态抄「喂食水母」：后台酿出新东西时 Octo Buddy 给轻量可见反馈，
  而不是完全静默——安静底色 + 可感知的在场。
- **不做**模型自主高频 Proactive 推送。

## 明确不做的

- ❌ 全量录屏 / 全量文件系统索引（成本高、错误伤信任、窥屏感）
- ❌ 扫描本机应用凭据（YouNavi 被扒出的工程红线，违反隐私铁律）
- ❌ 自研 Agent 编排栈（复用现有 AI SDK v6 链路）
- ❌ iOS 系统内录的任何尝试（物理不可能）
- ❌ 虚拟声卡方案（BlackHole 等，签名/打包/体验都差）

## 隐私基线（Cluely 泄露 8.3 万用户、Rewind 落盘未加密是前车之鉴）

- 本地优先：桌面端采集延续「IndexedDB/SQLite 为真实数据源、服务端仅
  同步备份」双存储铁律；token 只在主进程内存流转，不落盘。
- 排除列表：录课/截图支持按 App 排除（后续做）。
- 转写后删除原音频的选项（Granola 模式，后续做）。
- 关键帧/截图走不可猜路径（cuid userId + imageKey），与现有 audio 同级。

## 验收指标

- **推荐采纳率**（≈ AirJelly Proactive 接收率）：Hook 推荐的应用/复习卡
  被学生打开的比例——全链路（证据→线索→Next Step→推荐）健康度。
- 关键帧检测：precision/recall 用标注翻页时间点进 eval harness（仿
  `tests/eval/asr/graders/diarization.ts`）。
- 桌面壳：热键截图 3 秒内进收集线；loopback 录课转写质量不劣于麦克风。

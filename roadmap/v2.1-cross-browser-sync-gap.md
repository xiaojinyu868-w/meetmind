## 缺口描述

**现象**：浏览器 A 上录的课，浏览器 B 登录后看到了卡片，但点开课堂详情看不到转录、找不到锚点、没有 highlight。

**根因（已用代码确认）**：

1. **服务端只存了汇总文本，不存分段转录**
   - `WorkspaceCapture` 表只有 `normalizedText`（最多 8000 字符截断）和 `tutorContext`
   - 分段 `transcripts` / `anchors` / `summaries` / `highlights` / `notes` / `conversations` **没有对应的 SQLite 表**
   - 当前 `metadataJson` 里**有时**会有 `transcriptSegments`（视频导入路径塞进去的），但 `migrateLocalWorkspaceData` 这条路**没塞**

2. **客户端拉回时只重建 sourceItem，不回填 IndexedDB**
   - `useWorkspaceContextLoader.ts` Effect 1 拿到 captures 后只 push 进 `sourceItems`
   - 没有 `db.audioSessions.put` / `db.transcripts.bulkPut` / `db.anchors.bulkPut` 这种回写
   - 课堂详情、Tutor、Review 全部从 `db.transcripts.where('sessionId').equals(...)` 读 → 浏览器 B 上是空

3. **"双向同步"只做了 A→服务端的"上行"，没做服务端→B 的"下行"完整化**

## 修复方案（下一轮做）

### 选项 A：完整双向同步（推荐，但工作量大）

**Schema 改造**（`prisma/schema.prisma`）：
```prisma
model WorkspaceTranscriptSegment {
  id        String   @id @default(cuid())
  captureId String
  sessionId String   // 对应 IndexedDB 的 sessionId，跨设备一致
  startMs   Int
  endMs     Int
  text      String
  speaker   String?
  createdAt DateTime @default(now())
  capture   WorkspaceCapture @relation(fields: [captureId], references: [id], onDelete: Cascade)
  @@index([captureId])
  @@index([sessionId])
}

model WorkspaceAnchor { ... }     // 对应 db.anchors
model WorkspaceClassSummary { ... } // 对应 db.classSummaries
model WorkspaceHighlight { ... }    // 对应 db.highlightTopics
model WorkspaceNote { ... }         // 对应 db.notes
```

**服务端写入**（`workspace-account-service.migrateLocalWorkspaceData`）：
- 在保存 capture 时，同步 bulk insert 上述子表
- 用事务保证原子性
- 注意 batch insert 性能（一节 90 分钟课大约 800-1500 个 transcript segment）

**服务端读取**（`/api/workspace/current` 或新建 `/api/workspace/captures/:id/full`）：
- 默认列表只返回轻量 capture（避免回拉全量打死）
- 新增 lazy 拉取：用户点开课堂时按需拉该 capture 的完整子表
- 拉回来后写 IndexedDB

**客户端回填**（`useWorkspaceContextLoader` 或新 hook `useCaptureSync`）：
- 拉到 capture 后判断本地 `db.audioSessions.where('sessionId').equals(...)` 是否存在
- 不存在则触发"这节课从未在本地见过"的按需拉取流程
- 拉回数据 `db.transcripts.bulkPut(...)`，等价 IndexedDB 状态

**预估工作量**：4-6 小时（含测试）

### 选项 B：metadata 内塞 transcript（短期妥协）

把 `transcriptSegments` 数组塞进 `WorkspaceCapture.metadataJson`：
- ✅ 不动 schema
- ❌ JSON 字段无法索引、超大（一节课的 transcript 可能 100KB+）、单条记录会膨胀
- ❌ 触发 SQLite 单字段读写性能下降
- ❌ 是技术债，半年内必然要拆出来

**不推荐**。

### 选项 C：明确告知用户"跨设备只看摘要"（最简）

- 不做架构改造
- UI 上：浏览器 B 打开 capture 时，如果本地没有对应 sessionId 的 transcript，显示"这节课在另一台设备上录制，仅可看摘要。在原设备打开可看完整转录"
- ✅ 0 工作量
- ❌ 体验割裂，与"长记忆系统"产品定位冲突

# 学会学习（Learning to Learn）

> 上游：THU-MAIC/OpenMAIC（MIT）`skills/agent-runtime/learning-to-learn/SKILL.md`，2026-09 vendor，合规说明见 `../NOTICE`。
> 裁剪：删除多代理 roster 段落（本课堂是单一老师声音）与 stage-design 引用；嵌入点从页面规划改写为口播、板书与 discussion 节奏。平行目标纪律、两条内容红线与质量关口原样保留。

把学习策略与元认知作为**平行目标**嵌入概念主课：不替换学科概念主线，而是改变学生如何经历、检查和巩固这些概念。

如果同时使用 `/understanding-by-design`，先确定大概念、基本问题与表现性任务，再嵌入学习策略；如果同时使用 `/social-emotional-learning`，让两类平行目标服务同一概念任务，不要各自另起一条课程主线。

## 先声明平行目标（教师侧，不宣读）

开始设计前分别声明：

1. **概念目标**：学生最终要理解、解释或迁移什么；
2. **学会学习目标**：学生要练习哪一种学习动作，以及什么行为能证明它发生了。

每一个学习策略都要能回答"它在服务哪个概念理解"；答不出的嵌入删除。优先选择最贴合任务的 1–2 种策略，不要在一节课里罗列整套学习科学术语。

## 两条内容红线

1. **规划标签不进课堂**：`学习缝`、`元认知`、`教学意图`、`平行目标` 等内部框架词只用于你的思考，不作为学生可见的板书标题、正文或口播术语。
2. **策略用动作语言说**：学生听到的是能立即执行的动作，而不是技术术语：

- 检索练习：说成"别急着翻，先把答案说出来"；
- 自我解释：说成"用自己的话给结论一个理由"；
- 先预测后验证：说成"先猜一下，再看对不对"；
- 间隔复习：说成"过几天我们再回来默一次"；
- 监控理解：说成"你是真的懂，还是只是感觉懂了？"

只有当学生明确要求学某种学习方法本身时，才把对应术语作为要学的内容。

## 四个嵌入点（活课堂版）

这些是节奏锚点，不是板书标题，也不要求各自单独成段：

1. **开场**：正式讲解前，让学生先调取已有知识、做出初步判断或口头写下预测（discussion 收集）。
2. **概念建立**：得出结论后，让学生用自己的话解释一次，并追问"为什么"。你可以示范一个不完整的解释，邀请学生补充或质疑。
3. **亲手做**：先让学生预测或作答，再给反馈；错误进入检查、补漏和重试路径，不能成为死路。出题走 `/quiz-maker`。
4. **收束**：同时收住"我理解了什么""我是怎样学会的""哪里还不确定"以及"之后如何再检索一次"。概念收获落板，学习过程反思口头说清。

## 质量关口

- 概念目标与学会学习目标分开声明。
- 每个嵌入点都标明它服务的概念与可观察的学习动作。
- 至少让学生实际经历一次主动回忆、自我解释或先预测后验证，而不是只听学习方法介绍。
- 受挫与错误后保留反馈、补漏和重试路径。
- 收束同时包含概念理解、学习过程反思与后续复习动作。
- 口播与板书不得出现内部规划标签。
- 不承诺"万能学习法"；需要比较研究证据时先核实来源，核不了就明说。

## 边界

本 Skill 用于把学习策略嵌入学科概念课，不用于以学习方法或学习科学本身为内容主线的独立课程。若学生要把学习法做成第二条完整课程主线，先口头确认范围。

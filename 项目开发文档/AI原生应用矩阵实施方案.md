# MeetMind AI 原生应用矩阵实施方案（SSOT v3）

> 本文档是应用矩阵的单一事实来源（Single Source of Truth）。
> 以“黄页导航页 + 独立应用窗口”为唯一产品方向。

## 0. 一句话定义

应用矩阵 Tab 是应用黄页，不是执行工作台。

- 在应用矩阵页只做“发现与进入”。
- 具体生成与渲染在应用独立窗口完成。
- 对话负责路由，不替代应用窗口。

## 1. 背景与目标

### 1.1 背景问题

历史版本把“应用入口 + 执行画布 + 通用卡片流”混在一个页面，导致：

1. 应用之间状态串扰（A 应用结果残留到 B 应用）。
2. 播客等强媒体应用被文本卡片稀释，体验不自然。
3. 新应用接入时容易被通用结构绑死，难以承载小而美创意。

### 1.2 目标

1. 把应用矩阵还原为黄页导航页。
2. 每个应用进入后都是独立窗口（像小程序）。
3. 应用窗口支持各自最佳呈现，不强迫卡片化。
4. 保留统一插件协议，降低开发熵。

## 2. 产品信息架构

| 层 | 职责 | 输出 |
|------|------|------|
| 应用矩阵黄页 | 展示应用卡片、分类、最近使用、推荐 | 应用入口 |
| 应用独立窗口 | 执行生成、渲染结果、应用内操作 | 媒体/文档/导图/测验等专属 UI |
| 对话层 | 意图澄清、应用推荐、跨应用调度 | 路由建议与快捷跳转 |

## 3. 硬边界（严格禁入清单）

以下能力禁止作为应用矩阵黄页卡片：

1. 数据采集入口：实时录音、视频导入、文档上传、粘贴文本。
2. 系统能力：登录注册、账号设置、权限管理、计费配额。
3. 全局导航能力：主对话入口、笔记总入口、教师端/家长端主流程。
4. 运维与诊断能力：日志、健康检查、网络诊断、故障排查。

判定规则：

- 若该能力属于“系统基础设施”，而不是“一次可完成的学习任务”，则不进入应用矩阵黄页。

## 4. 路由与状态模型

## 4.1 路由建议

1. 黄页页：`/app?tab=matrix`
2. 独立应用页：`/app/matrix/:appKey`
3. 可选深链：`/app/matrix/:appKey?session=:id&source=:type`

## 4.2 状态隔离规则

1. 应用结果缓存键必须包含 `sessionId + appKey`。
2. 切换应用时，默认清空当前窗口临时状态，再加载目标应用状态。
3. 不允许跨应用复用渲染结果对象。

## 5. 插件协议与渲染策略

## 5.1 统一协议（保留）

插件继续输出统一协议：

- `cards`
- `tasks`
- `trace`
- `render`（关键）

## 5.2 呈现优先级（调整）

1. 先消费 `render.mode` 做专属渲染。
2. 只有在应用未提供专属渲染时，才回退到通用卡片。
3. 黄页页本身不渲染执行结果。

## 5.3 媒体类特别规则

- 播客类输出必须以真实播放器为主，不展示冗余脚本文本主区。
- “播客”能力按产品定义归类为内容生成应用，不等同于通用 TTS。

## 6. 应用目录（精简版）

### 6.1 入选标准（防止“为了做应用而做应用”）

一个能力要进入应用矩阵黄页，必须同时满足：

1. 是高频学习任务，不是通用格式化输出。
2. 进入后能形成独立窗口体验，而不是继续堆通用卡片。
3. 结果可被用户直接消费（听、练、测、看图），无需二次加工。
4. 至少能定义一个可验证的闭环指标（完成率、复习率、纠错率、回放率）。

### 6.2 首批保留目录（5 个）

| 应用名 | appKey | 插件 | render.mode | 定位 | 状态 |
|------|--------|------|-------------|------|------|
| 课堂播客 | `audio-overview` | `studio-workshop` | `audio` | 真实播客播放器 | 已跑通 |
| 闪卡训练 | `flashcards` | `flashcards-lab` | `flashcards` | 主动回忆训练 | 已上线 |
| 测验工坊 | `quiz` | `quiz-arena` | `quiz` | 测后纠偏 | 已上线 |
| 思维导图 | `mindmap` | `mindmap-outline` | `mindmap` | 结构化导图 | 已上线 |
| 信息图工坊 | `infographic` | `studio-workshop`（待拆分） | `custom(image-first)` | 文生图输出学习信息图 | 规划中 |

### 6.3 暂缓目录（不在首批黄页展示）

1. 视频总览：更适合作为视频复盘视图能力，不是独立应用。
2. 学习报告：偏格式化总结，易退化为“写文档工具”。
3. 幻灯片提纲：偏演示文档生产，不是高频学习闭环任务。
4. 数据对照表：偏分析辅助工具，可作为应用内子能力而非独立入口。

## 7. 模型与服务边界（国内部署）

当前仅允许以下模型能力：

1. 阿里云百炼（Qwen）
2. 火山方舟
3. 中转站（用于聚合能力接入）

不直接接入国外官方模型通道作为主链路。

补充约束：

1. 信息图工坊默认走文生图模型链路（中转站能力优先）。
2. 课堂播客继续走火山播客专用接口，不与通用 TTS 混用。

## 8. 当前实现回写（截至 2026-02-15）

已完成：

1. 课堂播客闭环跑通（火山播客接口 + 真实播放器）。
2. 播客链路已改为播客能力优先，不走通用 TTS 兜底。
3. 闪卡/测验/思维导图已具备独立渲染模式。
4. 应用渲染优先 `render.mode`，减少通用卡片干扰。
5. 结果缓存已按 `sessionId + appKey` 隔离，切换应用不串结果。

待完成：

1. 将当前 Tab 内“执行区”下沉到独立应用路由（黄页与执行彻底解耦）。
2. 黄页页仅展示首批 5 个应用，并补齐分类、搜索、最近使用、推荐位。
3. 信息图工坊接入文生图模型，输出真实图像而非文本稿。
4. 应用窗口统一接入“返回黄页/切换应用”轻导航。

## 9. 交互规范

1. 黄页页点击卡片只做一件事：进入应用窗口。
2. 应用窗口主按钮文案统一为“生成{应用名}”。
3. 生成中状态使用应用级 loading，不阻塞黄页导航。
4. 应用失败时在窗口内给出重试，不污染其他应用。

## 10. 验收标准

每次发版至少满足：

1. 黄页页不显示执行结果内容。
2. 首批仅展示 5 个应用入口，不出现暂缓目录项。
3. 两个应用连续切换不会串结果。
4. 播客应用成功时首屏出现可播放音频控件。
5. 信息图应用成功时首屏出现真实图像结果。
6. TypeScript 检查通过，核心 E2E 回归通过。
7. 文案全中文、UTF-8、无乱码。

## 11. 对协作 Agent 的执行约束

1. 任何新应用先定义 `appKey + render.mode + 独立窗口交互`，再编码。
2. 不允许先做通用卡片占位后长期不收敛。
3. 文档变更必须同步 README 的“应用矩阵路线”章节。
4. 如实现与本文档冲突，以本文档优先并在 PR 中说明偏差原因。

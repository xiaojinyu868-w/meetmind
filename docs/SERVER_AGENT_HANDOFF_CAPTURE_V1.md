# MeetMind Server Agent Handoff: Capture V1

更新日期：2026-03-09

这份文档给服务器环境上的 agent 直接阅读。目标不是复述历史讨论，而是确保后续联调、开发、取舍都严格对齐产品定义。

---

## 1. 一句话结论

当前阶段，MeetMind 最重要的不是继续扩更多 AI 页面，而是把 `收集` 做成一个真正成立的产品。

**Capture V1 = 一个微信式的学习上下文聊天流。**

用户只是把学习现场里的内容发给 MeetMind：

- 左边发原声
- 输入框里做语音转文字
- `+` 统一上传图片、文档、音频、视频、链接
- 所有内容都先像消息一样进入流
- 后台再异步转录、OCR、解析
- 媒体消息成熟后，自然长出 `去复习`

旧的核心能力不能丢：

- 单节课长音频/视频
- 时间轴 / 时间戳
- 课堂问答
- 复习模式

新形态不是替换旧能力，而是把旧能力包进新的收集语法里。

## 2. 产品北极星

### 2.1 产品不是什么

不要把当前主产品理解成：

- 录音工具页
- 上传工具页
- AI 工作台
- 功能入口集合

### 2.2 产品是什么

当前更准确的定义是：

**MeetMind Capture = 一个 Capture First 的学习上下文收集器。**

它像微信一样自然输入，像 flomo 一样低摩擦收集，但最终会自然长出：

- 复习
- Tutor
- 回声
- 跨材料连接

### 2.3 当前阶段的优先级

先把 `收集` 做到极好，AI 尽量后置。

当前阶段重点不是：

- 前台大块 AI 洞察
- 复杂画像展示
- Tutor 多入口扩展
- 新的一堆一级页面

当前阶段重点是：

- 极低摩擦收集
- 原件优先
- 异步解析
- 与旧复习能力兼容

## 3. 产品原则

### 3.1 微信式交互语法

用户不该先想“我现在在用哪个功能”，他只是在“发给 MeetMind”。

稳定语法：

- 左侧：`原声`
- 输入框：文本输入
- 输入框内右侧：`听写`
- `+`：统一文件入口
- 右侧：`发送`

### 3.2 原件优先

任何输入都不应被解析结果吞掉。

原则：

- 原声先保留原始音频
- 图片先看原图
- 文档先开原件
- 视频先保留原视频

解析结果主要服务后台、Tutor、回声，不应默认霸占主消息。

### 3.3 先收，后理解

所有输入都应该：

1. 先进入收集流
2. 再后台异步处理
3. 不阻塞下一次输入

用户前台只需要明确感知：

- 我刚刚发出去了
- 它已经被收下

而不是看到系统解释自己做了什么。

### 3.4 不要系统话术抢戏

尽量避免在主流里出现下面这种话：

- 文件已加入当前收集流
- 系统正在后台解析
- 已接入，可用于后续理解
- 当前环境暂不支持……

如果必须提示，也应尽量轻、人话化，并放在次级位置。

### 3.5 兼容旧复习能力

任何媒体消息相关改动，都不能破坏：

- 音频 / 视频进入复习
- 时间轴 / 时间戳
- 课堂问答

理想状态：

- 用户先发一条媒体消息
- 后台转写完成
- 消息下面自然出现 `去复习`

## 4. 当前理想形态

### 4.1 页面结构

`收集` tab 应该像一条聊天式内容流：

- 顶部：很轻的聊天页头部
- 中间：内容流本身
- 底部：稳定输入栏
- 侧边：历史 / 回声 / 全部收集 / 微信输入 这类收集系统入口

不应像：

- dashboard
- workbench
- 表单上传页
- AI 展示页

### 4.2 支持的消息类型

当前消息对象应统一成：

- `text`
- `dictation_text`
- `raw_voice`
- `image`
- `file`
- `video`
- `link`

每种消息都应先有“原件消息态”。

### 4.3 各类输入的理想行为

#### 文本

- 直接发送
- 立即进入流

#### 听写

- 输入框内右侧按钮触发
- 文字直接追加到输入框
- 不抢原声入口

#### 原声

- 左侧固定入口
- 录一整段
- 停止后先发原始音频消息
- 聊天栏立即恢复
- 转录后台跑
- 转录成功后自然长出 `看文字 / 去复习`

#### 图片

- 支持相册选择、文件选择、桌面粘贴
- 主界面默认只看图
- 点击直接看原图
- OCR 默认不在主消息展开

#### 文档 / PDF / PPT / PPTX

- 先作为原件消息进入流
- 点击打开原件
- 后台慢解析
- 不在主消息默认展示解析正文

#### 音频 / 视频文件

- 先作为媒体消息进入流
- 后台转录 / 提取 / 建时间轴
- 成功后自然长出 `去复习`

## 6. 当前还没完全闭环的点

### 6.1 原声 / 音频 -> 转写 -> 去复习

这是当前最重要的闭环。

现状：

- 消息先发出去已经成立
- 本地 fallback 也补上了
- 但完整的“转写成功后自然长出 `去复习`，并稳定进入原复习页”仍需要服务器环境联调验证

### 6.2 视频文件媒体语法

视频已经能进统一上传链，但仍需继续打磨：

- 更像真正的媒体消息本体
- 更自然地进入复习

### 6.3 回来理由

历史、回声、全部收集已有骨架，但还没有完全形成 flomo 式的“回来继续记”的复利感。

### 6.4 微信真实回调

服务号轻录入骨架已经有了，但服务器上仍需真实联调：

- 消息推送
- 签名校验
- H5 承接
- openId 归属

## 7. 服务器部署前提

### 7.1 基础环境变量

至少需要：

- `DATABASE_URL`
- `DASHSCOPE_API_KEY`

### 7.2 媒体转写要真正跑通

以下变量非常关键：

- `PUBLIC_DOMAIN` 或 `PUBLIC_HOST`

原因：

- `/api/transcribe`
- `/api/transcribe-fast`

这些路线需要给上游 ASR 一个公网可访问的媒体地址。

注意：

- `transcribe-turbo` 已经支持本地 data URI fallback
- 但服务器正式环境仍应优先走公网可访问的正式路线

### 7.3 微信服务号

需要：

- `WECHAT_MP_TOKEN`
- `WECHAT_MP_PUBLIC_BASE_URL=https://你的域名`

当前默认按**明文模式**接服务号消息，不是 AES 加密模式。

### 7.4 微信登录（如果联调）

需要：

- `NEXT_PUBLIC_ENABLE_WECHAT_LOGIN=true`
- `WECHAT_REDIRECT_URI=https://你的域名/api/auth/wechat/callback`

### 7.5 Prisma

核心模型都在：

- `prisma/schema.prisma`

与当前主线强相关的模型：

- `User`
- `AuthProvider`
- `Workspace`
- `WorkspaceMembership`
- `WorkspaceCapture`
- `WorkspaceEcho`
- `WechatInboxMessage`

## 8. 服务器联调第一轮 checklist

### 8.1 Capture 主路径

必须跑通：

1. 打开 `/app?mobile=1`
2. 发一条文本
3. 发一段原声
4. 上传一张图片
5. 上传一个 PDF
6. 上传一个 PPT / PPTX
7. 上传一个音频文件
8. 上传一个视频文件

验证：

- 所有输入都先进入流
- 后台处理不阻塞下一次输入

### 8.2 原声 -> 去复习

必须重点验证：

1. 左侧原声开始录制
2. 停止后原始音频消息立即进入流
3. 聊天栏立刻恢复
4. 后台转写成功
5. 消息自然出现 `看文字 / 去复习`
6. `去复习` 能进入原复习页，并带上时间轴 / 时间戳

### 8.3 图片链

验证：

1. 主消息只看图
2. 点图直接看原图
3. OCR 不在主消息默认展开
4. Tutor / 回声仍能消费图片内容

### 8.4 文档链

验证：

1. 文档先像原件消息进入流
2. 点消息能打开原件
3. 不展示解析正文
4. Tutor 后续仍能消费解析结果

### 8.5 微信服务号

验证：

1. 发文字 / 语音 / 图片 / 链接
2. 自动回复里带 capture 链接
3. 打开 H5 承接页
4. 再进入 `/app?mobile=1&wechat_capture=...`
5. 内容成功进入当前工作区收集流

## 9. 当前阶段要继续做什么

### P0

- 跑通 `原声 -> 转写 -> 去复习`
- 跑通 `视频文件 -> 后台解析 -> 去复习`
- 保证所有原件先入流、处理不阻塞下一次输入

### P1

- 继续统一图片 / 文档 / 视频 / 音频的原件消息语法
- 继续削掉主流里的系统话术
- 让历史 / 回声 / 全部收集更像内容产品，而不是面板

### P2

- 把回声做成真正的回来理由
- 开始做跨课、跨材料、跨 session 的连接

## 10. 当前阶段不要做什么

服务器 agent 不要把时间花在这些方向：

- 重新做 AI 前台
- 扩 Tutor 页面数量
- 新增复杂一级页面
- 回到分类上传
- 在主流默认展示 OCR / 解析全文
- 再做回工作台 / 仪表盘形态

只要一个改动让产品更像“系统功能集合”，就说明偏了。

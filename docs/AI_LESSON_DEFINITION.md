# 一堂 AI 讲的好课：我们自己的定义（原则层 · 慢变，2026-09-13）

> 为什么要自己定义：我们不是在做"像人类老师的仿制品"。AI 老师有人类没有的长处（会算、会动、不累、记得你、能同时调动一整套模型），也有人类没有的短处（看不见你的脸、没有身体、会粗心、会等）。拿"像不像真课堂"当尺子，等于把长处按人类的形式削掉，再为短处道歉。所以先定义什么叫**AI 讲的好课**，再决定用什么系统形态去做——单模型、多智能体、子 Agent 编排，都是手段。
>
> 本文与 `docs/PRODUCT_TASTE.md` 同层：判断而非禁令，每条带理由与证据；想推翻，说清同一观察下新判断为什么更好。评测标准在 §5，系统形态在 §4，先看 §2 的定义。

---

## 1. 长板与短板（对照人类一对一老师）

**AI 比人长的地方——要发挥到极致，而不是藏起来装人**

| 长板 | 人做不到 / 做不好 | 我们的动作 |
|---|---|---|
| **算得对、画得准、能动** | 人在黑板上画不出精确的函数变换、转不了三维、拖不了参数 | 代码即真值（`<draw>`）：切线一定垂直半径；`time(t)` 让量真的在变；`param` 让学生自己拉 |
| **不累、不烦、可打断、可重讲** | 人讲第三遍会不耐烦；学生不敢第三次问 | 随时打断、换角度重讲是默认能力，不是"特殊照顾"；零社交压力——学生敢问蠢问题 |
| **记得你** | 人记不住你上个月错的题、上周听过的课 | 个人上下文（掌握轨迹 + 共享记忆）进 prompt：例子用你的、起点是你已经会的、上次卡的地方这次先补 |
| **知道你听过什么课** | 家教不知道你学校老师怎么讲的 | **收集线 × 课堂线**：你录过的课、收过的文章、错题都在——"你上周三老师讲到这里时是这么说的"。这是同类产品（豆包老师、千问智学、VideoTutor）都没有的 |
| **全学科、跨学科** | 一个物理老师不会顺手讲历史 | 允许并鼓励跨界类比；联网 grounding 拿真实数据 |
| **一整套模型随叫随到** | 人只有嘴和粉笔 | 图像、视频、代码、检索、计算器是老师的"教具柜"；备课与画图可以并行在后台做 |
| **可回看、可分享、可长出下一节** | 一节课讲完就散了 | 事件日志 → 回看 / 复习材料 / 出题；一节课是可分享的资产 |
| **便宜到可以天天上** | 一对一 ¥200–400/h | 目标 ≤ 人类 1/4；现状 ¥3–8/h（含图像） |

**AI 比人短的地方——要尽力弥补，而且弥补的方式要诚实**

| 短板 | 后果 | 弥补 |
|---|---|---|
| **看不见你**：没有表情、走神、皱眉这些信号 | 讲得再好也可能对着空气讲 | **感知层**：主动小问（`<ask>`）、"没听懂"一键、语音打断、拖动 / 点图即反馈、沉默时长与答题结果都进上下文；后续麦克风常开、（可选）摄像头 |
| **没有身体、声音平** | 缺临场感，像念稿 | 语气指令、停顿、思考声、按句节奏、板书与话同步；手与笔迹（低成本，见调研）；不做 3D 数字人（证据弱、成本高） |
| **会粗心** | 矩阵列写反、`const` 忘接、口播与图不一致 | 真值交给代码；审核角色在"到达 → 演出"的领先时间里复算并**在展示前**替换；已经上板的错误以老师的口吻**强调式纠正**（"注意这一步，正确的是…"），不道歉、不自嘲、不解释系统——**产品必须自信**（2026-09-13 产品判断：不自信的表现伤害信任，比错误本身更伤） |
| **要等**：首响 ~1 s、图 3–8 s、视频分钟级 | 冷场 | 到达 / 演出双时间轴、分镜预取、开课投机、永不在轮内等视频 |
| **没有真正的课堂经验** | 不知道这个知识点学生常在哪卡 | 从数据学：共享记忆里跨用户的常见卡点（匿名、聚合）回流到备课 |
| **没有同学** | 少了"别人也不会"的安全感与讨论 | 分享 / 裂变线；虚拟同学是可选项，不是默认（不为热闹加噪音） |
| **没有权威与情感联结** | 学生不信、不亲 | 稳定的人格与名字（分身线），记得上次，说"我不确定"时就说 |

## 2. 定义：一堂 AI 讲的好课

八条判断。每条写"是什么"、"为什么这是 AI 的课而不是人的课的翻版"、"怎么量"。

### 2.1 它是为这一个人讲的
起点是你已经会的，例子来自你的生活和你的错题，上次卡住的地方这次先补，讲完你能做对下一题。
*为什么*：人类老师做不到对每个学生的历史了如指掌；我们有个人上下文和你的课堂现场。
*怎么量*：一节课里引用学习者上下文的次数与相关性（自动）；讲完后同技能"下一题正确率"（Khan Academy 用的指标）；学生说"这个例子是我的"的比例（抽样）。

### 2.2 它讲的每一个"真"都是真的，并且始终自信
数学与物理的画面由代码构造，不是模型手画；事实有来源；错误尽量在展示前被拦住；已经上板的错误以强调的方式纠正，而不是道歉。老师不说"我可能错了"，遇到真不确定的事实说的是动作（"这个数我们查一下"），不是犹疑。系统层的失败（一张图没画出来）也不向学生"坦白"——板上不出现"老师没画出来"这类话，老师接着讲，失败只进老师自己的上下文。
*为什么*：人类老师也会写错，但学生信他；AI 一错就失去信任，一不自信也失去信任——正确性是 AI 课的生命线，自信是它的表达方式。真值由代码保证，正是 AI 能比人更可靠的地方。
*怎么量*：draw 报错率与自愈率（且自愈在展示前完成的比例）；关键结论复算通过率；抽样人工审内容错误率；板上"系统自白"文案出现次数（目标 0）。

### 2.3 它让抽象的东西看得见、动起来、能摸
量在变、图在转、点在走，学生能拖参数、指着图问；能算的运动都真的算。
*为什么*：这是 AI 相对黑板最不对称的优势。一个好人类老师用手势和语言让你"想象"，AI 让你"看见"并"操作"。
*怎么量*：每分钟画面有变化的比例（目标：每 15 秒有一处）；可交互块占比；学生操作（拖动 / 点图）次数；有真值内容用 `<draw>` 而非 `<svg>` 的比例。

### 2.4 它随时可以被打断，并从那里接着讲；它的提问是可以"点"的
打断三拍内有回应；换角度重讲不重复原话；追问不丢上下文；学生指着板上任何东西问，老师知道指的是什么。**老师的检验默认给出可点的答题动作**——选项、点图上的某处、把参数拉到某个值、填一个数——而不是只抛一个开放问题等学生打字或按住说话；每个选项对应一种具体的理解或误解，选了哪个就是下一轮最好的上下文。自由输入与语音永远在旁边，但不是唯一入口。
*为什么*：人类课堂里打断是有社交成本的，AI 课里打断是免费的——所以 AI 课的默认节奏应该比人类课更"对话"。而对话要低摩擦：点一下 1 秒，按住说话 5–10 秒；豆包老师的"你理解了吗 → 按住语音回答才继续"是反例（门槛高、且只能答是否）。Brilliant / Synthesis 这类"做中学"产品每 20–30 秒就有一次可点的检验，是这条的标杆；Khanmigo 2026-08 的"拖顶点老师响应"是同一方向。学习科学上，构造良好的选择题（干扰项对应真实误解）有可靠的检验与学习效果，且比开放题更容易得到诚实回答。
*怎么量*：打断到首响时间；重讲与原讲的相似度（要低）；指图引用命中率；**检验的应答率**（可点的应远高于开放问题）；选项命中误解后老师是否针对性地讲。

### 2.5 它有声音、有节奏、有停顿
第一秒开口，两句话内板上有第一笔；说一段画一段；口播不念 LaTeX、数字算好再念；停顿是内容的一部分。
*为什么*：临场感不来自像人，来自"此刻正在为你生成"——节奏对了，学生感到的是有人在教，而不是在放片。
*怎么量*：首响 ≤ 1.5 s；首笔 ≤ 10 s；音画同步偏差；连续无画面变化的最长时长。

### 2.6 它知道你学到哪了，并诚实地告诉你
课中有小检验，课后掌握轨迹写回共享记忆，下次从这里开始；不为"完成课程"而假装你会了。
*为什么*：人类老师的"你懂了吗"是礼貌，AI 的检验可以是真的，而且能跨课累积。
*怎么量*：每节课检验次数与形式多样性；掌握轨迹更新率；学后测（TeachQuiz 式）。

### 2.7 它便宜到可以天天上、可以为一个人讲十遍
成本 ≤ 人类一对一的 1/4，目标 ¥5–10/小时以内。
*为什么*：便宜不是妥协，是产品定义的一部分——"一对一"只有在天天上得起的时候才是一对一。
*怎么量*：每课成本（模型 / TTS / 媒体分项，已有 `liveCostCny`）。

### 2.8 它可回看、可分享、会长出下一节
一节课讲完是资产：回看重放、复习材料、出题、分享给同学；老师记得你这节课讲过什么，下节课接着来。
*为什么*：人类课堂的知识随下课蒸发；AI 课的每个字都在日志里，这是"越用越厚"的来源。
*怎么量*：回看率、复习材料生成率、分享率、连续课的上下文引用。

## 3. 形态推论：它是什么、不是什么

**是**：一块会算、会动、会听、记得你的板，加一个不会累的声音，围着"这一个人"讲。
**不是**：人类课堂的录像替代品。

我们**故意不要**的人类课堂元素：
- 数字人老师（露脸不增益、3D 不如 2D、成本等于全部预算）
- 固定 45 分钟与固定进度（AI 课的单位是"一个想法"，学生决定下一步）
- 板书擦了就没了（我们的板可回看、可回滚）
- "举手才能问"（打断免费）
- 生成的"逼真"视频讲物理（逼真但可能错，比示意图更糟）

我们**要而人类课堂没有**的元素：
- 参数滑块、可拖的顶点、会转的三维
- 你自己的课堂录音与笔记作为例子来源
- 老师当众复算、当众改错
- 一节课讲完自动长出的复习与题
- 可以点的检验：选项 / 点图 / 拉参数 / 填数，选错直接暴露误解

## 4. 系统形态：一位主讲 + 几位不打扰的同事

好课不要求单模型全能。一个老师上课时，身后可以有备课的、画图的、审稿的、看学生脸色的、翻档案的——但**学生只听见一个声音，且这个声音永不因为同事而卡顿**。这是多智能体编排的唯一硬约束；其余按 Less Structure：同事给主讲的是**上下文**，不是指令。

| 角色 | 做什么 | 何时 | 可用模型 | 现状（2026-09） |
|---|---|---|---|---|
| **主讲** | 直出标签流：口播、板书、动作 | 每轮，流式，首响 ~1 s | GLM-5.3-Flash（低思考） | `teach-live-service` 一轮一次 streamText |
| **备课** | 开课前 / 上一页讲到一半时准备下一页：课程骨架、要用的例子（从学习者上下文与课堂现场里找）、要预取的图 | 与主讲并行，领先一页 | 可用更强 / 更慢的模型（有时间） | 无；`learner` 切片进 prompt 是雏形 |
| **画师** | 检索真图 / 快模型生图 / 离线情境片；给图加标注底 | 收到备课或主讲的媒体请求就开始，成了再上板 | 检索 → FLUX schnell / GPT-image-2 / Qwen-Image；视频离线 | `live-image`（qwen-image-3.0-pro，81 s）是雏形 |
| **审核** | 复算关键结论、跑一遍 draw、看口播与图是否一致；发现错就以一句上下文告诉主讲 | 每轮结束 / 段闭合时，异步 | 小模型 + 代码 | `draw-fix` 自愈、代码版 critic 是雏形；内容复算无 |
| **观察** | 看学生：沉默多久、答错什么、点了哪、打断说了什么、拖了哪个参数；把"他可能卡在这"写成一句话 | 持续 | 小模型或规则化信号 + 模型判断 | `boardNote` 通道已有，只传 draw 报错；沉默 / 答题信号未接 |
| **记忆** | 读：学习者上下文；写：这节课的掌握变化、卡点、用过的例子 | 开课读、课中写、课后归档 | — | `context/`（Hindsight）+ `learner-context-provider` 已有；teach-live 写回未接 |

编排原则（有理由，可偏离）：
1. **主讲永不阻塞**——同事的产出以"下一轮的上下文"或"段边界的旁白"进入，不插在句子中间。理由：首响与节奏是 2.5 的命。
2. **上下文而非指令**——观察说"他连续两次答错，第二次沉默了 12 秒"，不说"请换例子"。理由：判断留给主讲，同事看到的只是局部。
3. **每个角色可换模型**——主讲要快，备课可以慢而强，审核可以小而多次。理由：成本与延时分配在角色上而不是全局。
4. **预算是上下文**——每课媒体预算告诉主讲与画师，让它们权衡，不写硬上限。理由：与产品 Taste 一致。
5. **先有角色再有框架**——上述六个角色用现有的 service + 事件总线就能长出来（备课 = 开课时一次并行调用；观察 = 事件聚合 + 一次小模型判断；画师 = 现有 live-image 换源）；等它们真的各自独立成流程，再谈子 Agent 框架 / 多智能体编排库。理由：不为编排而编排。

### 4.1 架构决策（2026-09-13）：不引入多智能体编排框架，说话的那条路永远是单模型单流

**现状**：teach-live 一轮 = 一次 `streamText`，模型直出标签流 → 服务端解析 → 事件总线 → SSE → 前端按语音节奏演出；旁路是 TTS（按句）、异步生图、draw 自愈（按需一次小调用）、内联计算。没有编排器，没有 agent 框架；三条线（codex / engine / live）并存，前两条也都是"单 agent + 工具"。

**已有的实测**（`out/teach-harness-ab/REPORT.md`）：把 OpenMAIC 的 LangGraph director 多智能体栈忠实移植过来对比单流直出——首字 9.3 s vs 4.8 s，输入 token 9,830 vs 587（×17），成本 ×3，judge 分相同（5.0 / 5.0）。多智能体编排放在说话路径上，是纯成本。

**框架成熟度**（2026-09）：LangGraph 1.x GA、Microsoft Agent Framework 1.0（2026-04）、OpenAI Agents SDK、Google ADK、Claude Agent SDK 都算生产可用了——但它们解决的是回合制、工具调用、可恢复的长流程；没有一个是为"亚秒级首响、按语音节奏流式讲课"设计的。引入它们不解决我们的约束（延时、音画同步、流式），只增加抽象层与 token。市面上也没有产品在实时讲课路径上用多智能体：豆包老师 / 千问智学 / Khanmigo / VideoTutor 公开信息都是单模型 + 渲染层（VideoTutor 是多阶段管线，不是多智能体）；OpenMAIC 是研究 / 开源，且以预排脚本为主。

**决定**：
- 主讲 = 单模型单流，不变；模型升级（Flash → 下一代）由它全额继承（Bitter Lesson）。
- "同事"= 现有事件总线上的**异步旁路服务**：每个是一段代码或一次小模型调用，产出的是**下一轮的上下文**。这是多阶段 / 旁路，不是多智能体编排。
- 复用现有件：观察的最便宜信号是学生**点了哪个选项 / 拖了哪个参数**（§2.4），走已有的 `boardNote` 通道；审核复用 draw 自愈的模式（一次调用、有验证）；画师复用 live-image 换源；记忆复用 `context/`。
- **重新评估的条件**：当某个角色需要自己的多轮状态并且要与另一角色对话（不再是一次性产出上下文），或者需要跨会话的可恢复长流程（课程级备课 / 离线建库）——那时对**离线部分**用图式编排（LangGraph 类），说话路径仍不碰。
- 风险登记：单流的上限 = 主讲模型的上限；缓解是给它更好的上下文（备课）、更宽容的运行时、可换更强的模型；不是加更多说话的模型。

### 4.2 虚拟同学（2026-09-13）：不做，直到有证据学生需要

OpenMAIC 的实现（vendor 源码 `lib/orchestration/director-*.ts` + `prompts/templates/agent-system-wb-student`）：一个 director LLM 每轮从 agent 注册表（teacher / assistant / student 各带 persona 与 priority）里决定下一个谁说；每个发言者是一次独立的 LLM 调用，学生 agent 默认只说话不上板（被邀请才画，且要避开板面冲突表）；`discussion` 动作触发圆桌；TTS 按 persona 出声。代价就是上面的 ×17 token 与 9 s 首字。它提供的价值——"有人问出学生不好意思问的问题、有人说出典型误解"——我们用**可点检验的干扰项**（每个错误选项就是一个典型误解）能拿到大半，不需要第二个声音。若日后要做，形态是一个"同桌"而不是一间教室，且只在学生沉默时出现。

## 5. 好课评分卡（先量能自动量的）

| 维度 | 指标 | 目标 | 来源 |
|---|---|---|---|
| 为你讲（2.1） | 学习者上下文引用次数 / 相关性；下一题正确率 | 每课 ≥ 2 次有效引用；正确率上升 | 事件日志 + 应用矩阵 |
| 真（2.2） | draw 报错率、自愈率、复算通过率、抽样内容错误率 | 报错 < 5%，错误率 < 2% | `teach-live-repair`、审核角色 |
| 看得见（2.3） | 画面变化间隔、可交互块占比、学生操作次数 | ≤ 15 s 一处变化 | 事件日志 |
| 可打断（2.4） | 打断首响、重讲相似度、指图命中率 | 首响 ≤ 1.5 s | 事件日志 |
| 有节奏（2.5） | 首响、首笔、音画偏差、最长静止 | 首响 ≤ 1.5 s、首笔 ≤ 10 s | e2e |
| 学到哪（2.6） | 检验次数、轨迹更新、学后测 | 每个想法 ≥ 1 次检验 | 事件日志 + 记忆 |
| 便宜（2.7） | 每课成本分项 | ≤ ¥10/h | `usage` 事件 |
| 资产（2.8） | 回看率、材料生成率、分享率 | — | 产品埋点 |

主观维度（学生：像有人在教我吗；老师视角：这节课我愿意让我的学生上吗）用抽样访谈，不做打分表。

## 6. 怎么做：探索上限、弥补弱项，不加次要设计（2026-09-13 定稿）

前两稿的问题是把"好课"翻译成了功能清单（手、笔声、镜头、回放卡、选项样式……）。那些是设计，不是本质。本质只有两件事：**AI 的上限被什么卡住了，就拆掉什么；AI 弱在哪，就只补那里。** 其余一概不加。

### 6.1 卡住上限的四样东西与对应的动作

| 卡住上限的 | 事实 | 动作 | 验证 |
|---|---|---|---|
| **模型看不见自己画的** | 它写 draw 代码、写口播，从不看渲染结果；人类老师看着自己的板讲 | **渲染器进环，在演出前**：段一闭合就渲染，检查者（代码 + 必要时 VLM）在"到达 → 演出"的领先时间里看一眼，有问题让模型改——学生看到的永远是改过的版本。Code2Video 的 Critic、ManimAgent 的 renderer-in-the-loop 都是同一件事，都带来两位数提升 | 展示前修正率；抽样视觉质量（VLM 评）；draw 报错率 |
| **模型看不见学生** | 它只收到打字的消息与偶尔一条 boardNote；人类老师看着学生的脸 | **感知通道**：学生的一切动作与不动作——点了板上什么、拖了哪个参数到哪、沉默多久、回看了哪页、答了什么——都成为下一轮上下文；老师提问时可以随手给出可点 / 可拖 / 可填的作答形式（这是能力，不是题型设计）| 上下文里学生信号的条数；老师是否据此改变讲法（抽样） |
| **模型本身的天花板**（Flash 档、不许思考） | 为首响与成本选了 Flash + `reasoning_effort=low`；上限就是它的上限 | **先量再定**：同一协议、同一题目，前沿模型（Gemini 3.x Pro / Claude / GPT）对照 Flash，看差多少、差在哪；若差距大 → 两层：**强模型思考着备课**（骨架、例子、第一张图）与 Flash 出声并行，第二轮起接上；若差距小 → 瓶颈在协议，回到上一行 | 对照实验的首笔 / 图的丰富度 / 错误率 / 评委分 / 学后测 |
| **我们自己加的天花板** | prompt 里按今日模型与 TTS 写死的数字（首句 ≤25 字、一轮 400–900 字、2–5 块、每 15 秒一变）、只鼓励 draw 而冷落通用逃生口 | 在强模型上跑**无约束对照**，数据决定留哪条；`<widget>` / 通用 JS 是一等公民，**不再新增 draw 原语**（camera / drag / morph 一律不加，除非对照实验证明模型用通用代码写不出来） | 同上对照 |

### 6.2 弱项只补这些

盲（上面第一行）、聋（第二行）、粗心（真值交给代码 + 展示前修正，已有一半）、要等（双时间轴 + 投机预取，已有）、隔轮忘板（板面状态摘要进历史，已有一半）。**不补**：没有身体、没有同学、没有权威——这些用设计去补就是次要设计。

### 6.3 尺子

没有尺子谈不上上限：live eval 三件——**学后测**（TeachQuiz 式：VLM 或学生看完答题）、**VLM 看图**（布局 / 可读 / 与口播一致）、**延时分布**（首响 / 首笔 / 打断）。每次改协议、换模型、改 prompt 都跑。

### 6.4 明确不做（进 `docs/TEACH_LIVE_WOW.md` 备忘，不排期）

手、笔声、镜头原语、morph 原语、3D 拖拽原语、回放卡、选项卡片的样式设计、语音 barge-in 的专项、图像三源工程化。它们要么是次要设计，要么等上限实验之后再看是否还需要。

### 6.5 第一步

上限对照实验（一个下午）：4 个模型 × 6 个题目 × 现协议，量首笔 / 图 / 错误 / 评委 / 学后测。它回答唯一重要的问题——**瓶颈是模型还是协议**——后面的路径由它决定。

调研依据见 `docs/TEACH_VISUALS_FRONTIER_2026-09.md`；实现现状见 `docs/TEACH_TUTOR_ENGINE.md` §12。

# MeetMind Echo 产品定义

> 更新时间：2026-03-23
>
> 状态：已确认方向，待进入实现阶段

---

## 1. 背景：为什么重新定义 Echo

### 1.1 现状问题

当前 Echo 实现是一个**重型全屏面板**——有历史列表、筛选、chips 标签、统计数据，还有「去复习」「做成复习清单」等重动作。

问题：

- Echo 变成了一个操作中心，而不是一个反馈
- 用户打开 Echo 需要做决策：看哪条？要不要复习？做不做清单？
- 「去复习」「做成复习清单」的动线断裂——点击后体验不完整
- 与产品「先收，再懂，再教」的哲学矛盾：Echo 不应该给压力

### 1.2 参考分析：得到 GetSeed「发芽报告」

得到旗下的 Get笔记（GetSeed）是一个录音笔 + 软件产品。其「发芽报告」的设计：

- 用「播种 → 发芽 → 生长」的植物隐喻
- 用户录音后，AI 从多条录音中跨材料提炼话题
- 生成一份杂志式的长报告：5 个编号话题、叙事段落、来源标注、分类标签
- 需要用户手动点「发芽」按钮触发

**GetSeed 做对的事：**
- 给「等待 AI 处理」赋予了温暖、有期待感的情绪
- 跨材料提炼，不是逐条罗列
- 用户动作极轻——只需要录音和同步

**GetSeed 不适合 MeetMind 的地方：**
- 得到的用户是知识工作者的随想录音，MeetMind 的用户是学生的课堂原件——信息结构完全不同
- 长文档报告有阅读压力，与「不给压力」矛盾
- 没有传播属性——个人随想的提炼，别人看了没感觉
- 手动触发「发芽」意味着 AI 在等用户下令，不够自然

## 2. 产品 Taste

### 2.1 一句话定义

> **MeetMind Echo：你随手种下的，会安静地长成你意想不到的东西。**

### 2.2 Taste 的五个关键词

**安静** — Echo 不通知、不弹窗、不催促。它在你打开收集流的时候已经长在那里了。

**回来的比发出去的更好** — 用户发出去一节课的录音，回来的是「AI 听懂了这节课」。用户随口丢了一句困惑，回来的是「三天后你自己的课回答了它」。

**不急** — 没有「生成回声」按钮。像发酵——面团揉好放在那里，时间到了自己起来。Echo 出现的时机是 AI 真的有话可说的时候。

**小** — 一条 Echo，一个发现，三句话。不是五个话题的长报告。多个发现就多条 Echo，散落出现。小才不会变成压力，小才会被期待。

**有根** — Echo 里的每一句话都能指回一个真实的原件。不是 AI 凭空生成的洞察，而是基于用户自己的课堂、自己的材料。

### 2.3 Taste 的两面

| 维度 | 表达 |
|------|------|
| **对内（留存）** | 你随手种下的，会安静地长成你意想不到的东西 |
| **对外（增长）** | 一节课，一张卡，让别人看见你的学习 |

### 2.4 Echo 绝对不是什么

| 绝对不是 | 为什么 |
|---------|--------|
| 每日学习报告 | 日报是压力，不是回声 |
| 待办 / 复习清单 | 那是任务管理器，不是镜子 |
| AI 洞察展示面板 | 那是在炫技，不是在帮用户 |
| 需要「打开」的独立页面 | 需要打开就意味着会被忽略 |
| 信息流里的广告位 | Echo 必须每一条都对得起用户的注意力 |

## 3. Echo 的三层价值

来自产品讨论中确认的三个核心作用：

### 3.1 看见自己（Mirror）

让用户看见自己不知道的学习轨迹。

> 你这两周的 6 节录音里，有 4 次提到「边际成本」，但每次的理解角度都不一样。

> 你收集了 23 条材料，其中 18 条和机器学习有关。你正在进入一个新领域。

**本质：让忙碌的学习者停下来看见自己的轨迹。**

### 3.2 跳出茧房（Serendipity）

打破信息茧房，发现跨材料的隐含关系。

> 你 3 月 5 日的微观经济学课和 3 月 12 日上传的那篇论文，都在讨论价格弹性。课上老师用的是需求曲线，论文用的是实验数据——它们是互补的。

**本质：只有 MeetMind 能做到——因为只有它真正听过你的课、看过你的材料。**

### 3.3 灵感发芽（Sprout）

让用户随口的灵感自然接上后续材料。

> 你三天前说「傅里叶变换到底在干嘛」。今天张老师在高数课 47:20 讲了一个直觉解释。

**本质：用户付出的成本几乎为零（随口一句），但回报远超预期。这是 aha moment 最强的一层。**

## 4. Aha Moment 设计

### 4.1 核心原则：第一次 aha 不需要等

如果 aha moment 要等用户积累大量材料才发生，用户早走了。

**Echo 的第一个 aha 应该在用户第一节课转写完成后立刻发生。**

### 4.2 Aha 的递进结构

| 阶段 | 触发条件 | 用户感受 | aha 强度 |
|------|---------|---------|---------|
| **第一次** | 第一节课转写完成 | 「它听懂了我的课！」 | ⭐⭐⭐⭐ |
| **第二次** | 上传了一份相关材料 | 「它记得我之前的课，还把两个东西连起来了！」 | ⭐⭐⭐⭐⭐ |
| **第三次** | 早期碎片灵感被后续课堂回答 | 「我随口说的那句话，居然被回答了！」 | ⭐⭐⭐⭐⭐ |
| **持续** | 上下文越来越厚 | 「越用越懂我」 | 时间复利 |

### 4.3 第一个 aha 的具体形态

用户录了第一节课，转写完成后，收集流中出现：

```
┌─────────────────────────────────────────┐
│  ✦ 这节课的 3 个核心概念正在生长          │
│                                          │
│  📍 供需均衡                              │
│     老师在 12:30 用了一个水果市场的例子     │
│                                          │
│  📍 价格弹性                              │
│     老师说「这是期末必考的」(34:20)         │
│                                          │
│  📍 市场失灵                              │
│     你在这里标记了困惑 ❓                   │
│                                          │
│  它们会继续生长。下次收集相关内容时，       │
│  你会看到新的连接。                        │
└─────────────────────────────────────────┘
```

## 5. 增长引擎：课堂回声卡

### 5.1 为什么 Echo 可以驱动用户自传播

MeetMind 的用户是**学生**。学生的社交传播场景：**课堂是天然的群体场景。**

一个班 40 人听同一节课。一个人录了课，MeetMind 生成了回声卡——其他 39 人看到会想：「这什么 App？我也要。」

### 5.2 课堂回声卡的形态

Echo 在产品内部是安静的小卡片。但它有一个**可分享形态**——一张精心设计的图片卡：

```
╔═══════════════════════════════════════╗
║                                       ║
║   📖 微观经济学 · 第七讲               ║
║   2026.03.23 · 张明远老师              ║
║                                       ║
║   ─────────────────────────           ║
║                                       ║
║   🔑 这节课的 3 个核心                 ║
║                                       ║
║   1. 供需均衡                          ║
║      「价格不是人定的，                 ║
║        是市场自己找到的」               ║
║                                       ║
║   2. 价格弹性                          ║
║      老师说：期末必考 ⚡                ║
║                                       ║
║   3. 市场失灵                          ║
║      什么时候「看不见的手」会失灵？      ║
║                                       ║
║   ─────────────────────────           ║
║                                       ║
║   💡 一句话带走                         ║
║   「看不见的手不是万能的，               ║
║     它在公共品和外部性面前会失灵。」     ║
║                                       ║
║           ── MeetMind 回声 ──          ║
║                                       ║
╚═══════════════════════════════════════╝
```

### 5.3 用户分享的三重驱动力

| 驱动力 | 用户心理 |
|--------|---------|
| **我好厉害** | 我用 AI 整理了一节课的核心，我是认真学习的人 |
| **这个好有趣** | 卡上有金句、有重点、有老师原话，同学看了有共鸣 |
| **你也该试试** | 底部有品牌，同学问「这什么 App」，自然传播 |

### 5.4 增长飞轮

```
一个学生录了一节课
        ↓
MeetMind 生成「课堂回声卡」
        ↓
学生觉得这张卡很惊艳 → 第一个 aha moment
        ↓
学生截图发到班级群 / 朋友圈
        ↓
同班同学看到 → 「这是什么？我也要！」
        ↓
同班同学下载 MeetMind，录同一节课
        ↓
一个班级里有 3-5 个人在用
        ↓
更深的粘性 → 更多分享
```

**MeetMind 的增长单元不是「一个用户」，是「一个班级」。**

### 5.5 为什么比得到的发芽报告更有传播力

得到的发芽报告是**个人灵感整理**——分享出去，别人看到的是「你的随想提炼」，和他没关系。

MeetMind 的课堂回声卡是**共同经历的精炼**——同学看到的是「我们刚一起上的那节课的核心」，**和他直接相关**。

## 6. 场景聚焦策略

### 6.1 核心决策

**先打透「一节课」这个场景，再自然扩展到全场景。**

不从「笔记软件」入手。从「课堂」入手。

### 6.2 为什么选「课堂」而不是「笔记」

| 维度 | 课堂 | 笔记 |
|------|------|------|
| **信息结构** | 完整——有时间线、知识点、老师讲解逻辑 | 碎片——AI 处理碎片的能力有限 |
| **传播单元** | 一节课 = 40 个人共享的经历 | 一条笔记 = 私人的，没有传播力 |
| **aha moment** | 即时——第一节课转写完就发生 | 延迟——需要积累大量材料 |
| **用户旅程** | 清晰——上课 → 录音 → 看回声 → 分享 | 模糊——什么时候用？在哪用？ |
| **竞品壁垒** | 强——没有竞品真正「听过你的课」 | 弱——Notion、flomo 都能记笔记 |

### 6.3 两阶段路径

#### 第一阶段（当前）：课堂场景打透

**用户定义**：大学生，正在上课、考试、备考。

**核心动作**：录一节课 → 自动理解 → Echo 回声。

**Echo 类型**：

| Echo 类型 | 触发 | 内容 | 可分享 |
|-----------|------|------|--------|
| 课堂回声 | 一节课转写完成后 | 核心概念 + 老师金句 + 可能考点 | ✅ 回声卡 |
| 考点追踪 | 多节课积累后 | 「这个概念出现了 3 次，可能是重点」 | ✅ |
| 困惑提醒 | 用户标记困惑后 | 「你在这里卡住了，Tutor 可以帮你」 | ❌ 私密 |

#### 第二阶段（课堂打透后）：自然扩展

当用户因为课堂场景留下后，自然开始往里面扔其他东西——论文、笔记、灵感、链接。

Echo 自然扩展：

| Echo 类型 | 触发 | 内容 |
|-----------|------|------|
| 跨材料连接 | 两份材料有关联 | 「这篇论文和上周的课讲的是同一件事」 |
| 灵感发芽 | 早期碎片被后续材料接上 | 「你之前的困惑，被今天的课回答了」 |
| 学习画像 | 积累到一定量 | 「你最近的精力集中在这三个方向」 |

### 6.4 与原有产品定义的关系

这个聚焦策略不否定海报上的全景产品图。海报上的一切——智能收集、教育记忆大模型、AI 私教——都对。

但海报是全景图，是给投资人看的。

**产品落地需要一个尖刀口：**

> 一个大学生录了一节课。MeetMind 帮他听懂了这节课，并且生成了一张让他忍不住分享到班级群的回声卡。

**这一个场景打透，其他所有东西自然长出来。**

## 7. Echo 形态设计原则

### 7.1 在收集流中的形态

Echo 是收集流中自然出现的一张特殊卡片。不是独立页面、不是独立 tab。

**设计约束：**

1. 一条 Echo，一个发现，三句话
2. 3 秒可读——不需要展开、不需要滚动
3. 来源可触——关联材料以轻标签出现，点击回到原件
4. 动作可选但不强迫——「问问 Tutor」「重听这段」轻轻长在卡片上
5. 时间有节奏——不是实时生成，而是积累到有价值时自然出现

### 7.2 可分享的回声卡

当一节课的 Echo 生成后，用户看到一个「分享」按钮，点击生成精美的图片卡：

- 课程名、日期、老师名
- 核心概念（2-3 个）
- 老师金句
- 一句话总结
- MeetMind 品牌

### 7.3 触发节奏

| 触发条件 | Echo 类型 |
|---------|----------|
| 一节课转写完成 | 课堂回声（核心概念提取） |
| 近 3 天内收集了 5+ 条材料 | Mirror（你最近在关注什么） |
| 两条以上材料存在跨课主题连接 | Serendipity（意外发现） |
| 有未解决的困惑点 + 新材料可能相关 | Sprout（灵感发芽） |

**关键：宁可少出，不可多出。** Echo 一旦变成每天都有的固定报告，就失去惊喜感，变成噪音。

## 8. 与现有 Echo 实现的差异

| 维度 | 现有实现 | 新定义 |
|------|---------|--------|
| 形态 | 全屏面板 + 历史列表 | 收集流中的轻卡片 |
| 触发 | 手动 / 自动刷新 | AI 有话可说时自然出现 |
| 信息量 | 重——chips、筛选、统计 | 轻——一个发现、三句话 |
| 动作 | 重——去复习、做复习清单 | 轻——可选的 Tutor / 原件跳转 |
| 传播 | 无 | 课堂回声卡可分享 |
| 节奏 | 固定——每日刷新 | 自然——有价值时才出现 |

## 9. 核心比喻

> 得到 GetSeed 像一个花匠——你把种子交给他，他帮你培育，给你一份种植报告。
>
> MeetMind Echo 像山谷——你在山谷里说话、走路、学习。山谷把你的声音反射回来，让你听见自己没注意到的东西。山谷不会追着你说「你有一条新的回声」。它只是在你安静下来的时候，让那些声音自然地回到你耳边。

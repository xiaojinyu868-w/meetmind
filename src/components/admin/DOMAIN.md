# Components: Admin

> 管理员专属的 AI 可观测与控制界面。普通用户不可见，也不应把调试信息混入 To C 学习体验。

## 文件

| 文件 | 职责 |
|------|------|
| `AiControlWorkbench.tsx` | 独立 AI 控制中心：按 Tutor / 理解层 / 应用分组展示十四条真实链路；提供上下文地图、样例/现场预览、线上与编辑版真实结果试跑、追加指令、模型路由、草稿、发布与回滚 |
| `CostPanel.tsx` | 管理员成本视图（积分影子计量 Phase 1）：挂在 Workbench 顶部，7/30 天切换 + feature × model 聚合表格 + 每日趋势条，数据只读取自 `/api/admin/costs` |
| `AdminLensProvider.tsx` | 管理员会话级“管理视图”状态；管理员默认看到普通用户界面，主动开启后页面内透镜才出现，退出登录或新会话自动关闭 |
| `AdminAiInspectorLink.tsx` | 嵌入产品现场的管理员透镜；原地侧栏重建当前线上版本接收的上下文与最终系统输入，并将本次上下文暂存在当前浏览器供控制中心继续调试 |

## 依赖边界

- 所有服务端读写只走 `/api/admin/ai-control`，组件不直接访问 Prisma。
- `AdminAiInspectorLink` 必须同时检查 `user.role === 'admin'` 和管理员主动开启的“管理视图”；普通用户不渲染占位，管理员默认也必须体验与普通用户相同的界面。
- “管理视图”只用 `sessionStorage` 记住当前浏览器会话，不写数据库；退出账号或新会话恢复关闭，避免管理员长期生活在被调试控件污染的产品里。
- 现场侧栏通过管理员 API 使用当前线上 override 重建输入；展示的是请求模型，provider 故障后的实际备用模型以后端 trace 为准，不得冒充真实最终通道。
- 现场上下文只写 `sessionStorage`，不写日志、不写 URL、不额外持久化；普通用户不会下载或渲染这些调试信息。
- 管理员只能追加行为指令和选择已注册模型；完整基线 prompt 与不可覆盖合同由服务端控制。
- “理解层”目前包含深度学习意图确认和长期学习理解整理；它们与真实 `/api/tutor/intent`、`/api/tutor/memory` 共用 prompt 与 user input 拼装，不是仅供展示的后台副本。
- “应用”已覆盖应用矩阵全部六类：闪卡、测验、思维导图、考试速查表、课堂信息图与课堂播客。控制中心和插件共用 `app-prompts.ts`；导图保持单课轻结构 Markdown，速查表保持跨课 / 考试可打印 JSON，信息图保持手机可读的单一视觉命题，播客把无时间戳朗读语料与章节定位证据分开，不能用一套万能模板抹平。发布后的模型覆盖与追加指令直接进入 `/api/apps/execute`；数据库控制读取失败时必须回退代码基线。
- 回答对比只在管理员主动点击后调用模型：同一问题与上下文分别运行当前线上 override 和编辑中的 override，不写入用户对话、不自动保存或发布；两版各消耗一次模型调用。
